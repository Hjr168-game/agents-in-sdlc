前面为项目添加了一项小功能，但更大的更改需要更完善的流程。GitHub Copilot app 可以配合组织现有的流程，帮助我们用正确的方法构建正确的功能。从本课开始，你将通过几节课遵循典型的智能体驱动开发流程：从议题着手构建新功能，确认代码有效、功能符合预期，最后成功合并到项目。

> [!NOTE]
> 后续功能开发将继续使用同一会话。通常会为不同类型的文件创建不同会话或 PR，但本研讨会会简化流程，以便聚焦核心概念。

本课将学习如何：

- 根据 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中定义要求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续开发此功能时，还会更新存储库指令、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 智能体，并打开功能 PR。

## 场景

Tailspin Toys 的游戏目录不断扩展，访客需要按类别和发行商筛选游戏。待办事项中的议题描述了该功能，但组合类别等细节需要在编写代码前确定。你将使用 Plan 模式确定方案，再授权 Autopilot 在明确范围内实现功能。

## 背景

将 AI 编码智能体引入开发流程，并不会改变软件开发的基本原则；这些原则反而更重要了。大多数开发人员都会遵循类似的流程：

1. 打开已创建的议题，查看需要完成的工作详情。
2. 规划实现方案。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体步骤会因团队和组织而异，但大多数流程都与上述做法类似。

遵循这种标准流程，可以确保 AI 生成的代码满足要求，并与人工编写的代码一样经过审查。

## 会话模式

**会话模式**决定智能体可以自主执行工作的程度。可以通过提示词字段下方的下拉菜单设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你输入后再继续。
- **Plan**：智能体先制定计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体自主工作，包括编写代码、运行测试并不断迭代，无需等待输入。

先在 Plan 模式中审查计划，然后使用 Autopilot 实现。

## 从议题启动会话

开始筛选工作前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已创建的议题，无需再创建。
2. 选择 **New session**，并选择基于更新后 `main` 创建的 **new working tree**。

    ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果这些命令在终端中有效，但在会话中无效，请检查 app 的 PATH 或版本管理器设置，然后完全退出并重新打开 app。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划让你能在 Copilot 编写代码前审查实施方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并对照议题的验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时如何处理。

计划应使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。批准前先要求修订不符合决定的计划内容，并保留议题 URL 和已达成共识的澄清内容，供后续验证时使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中含义相同的选项。确认当前模式，而不是假定批准后会自动切换模式。确认模式指示器显示 **Autopilot**。

Copilot 会开始实现功能，按照既定计划逐步生成代码、运行测试并进行迭代。

> [!NOTE]
> 批准计划后，实现可能立即开始，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再确认检查已完成。只停止自己启动的服务器。

## 审查并验证实现

与其他代码一样，生成的代码也需要在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 对照议题和已批准的澄清内容检查结果，包括多个类别和发行商的组合。确认更改符合现有存储库指令。
3. 检查 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，也可能复用本地服务器；确认被测服务器属于此工作树，而不是之前课程的服务器。

## 试用新功能

代码看起来没问题，但是否能运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示词，让 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果与该类别匹配。清除筛选条件，再选择一个发行商，确认结果与该发行商匹配。
4. 同时应用类别和发行商筛选条件，将结果与议题和已批准的计划进行比较。如果支持多个类别，还要验证已经确定的组合行为。
5. 尝试组合出没有匹配游戏的筛选条件，并检查空状态。清除或重置筛选条件，确认完整列表重新显示。
6. 完成后，使用以下提示词让 Copilot 停止为此会话启动的开发服务器，并关闭浏览器画布：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 在后续课程中继续使用此会话

现在不要创建或合并筛选功能 PR。练习 4 至练习 8 会继续使用此会话、工作树和分支。下一课会将自定义指令应用到筛选代码，然后添加技能和 QA 改进，最后在练习 8 中创建并合并合并后的 PR。停止开发服务器后，可以暂时离开会话；下一课再返回同一会话。
