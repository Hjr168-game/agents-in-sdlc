GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、こうした作業が自分のマシンでリアルタイムに進むため、ツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って会話を調整したり作業を広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューし、採用します。
- 作業中のエージェントに指示を追加し、ハイコントラストモードに加えてライトモードの切り替えを依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。最初から新しい会話を始めずに、既存のセッションに指示を追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集は、差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消して、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などでツールが許可を求めると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方針、設定したローカルストレージの方法を引き続き利用できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合は、チャット入力欄の横にある **Stop** ボタンで作業を停止してから、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも迅速に調整できます。追加のプロンプトを使って、変更を依頼したり (「CSS を簡潔にしてください。セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正したり (「切り替えを 3 つに増やさず、既存の設定パネルにライトモードを追加してください」)、作業範囲を広げたり (「両方の切り替えにキーボードショートカットも追加してください」)できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存など、カスタムエージェントのアクセシビリティの方針が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、作業中のセッションを監視して方向付けました。ファイル編集を確認しながら採用または取り消しを選び、コンテキストを保ったまま追加のプロンプトを送って作業を広げました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を採用または取り消す方法
- 追加のプロンプトで作業中のセッションを調整する方法

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが行った変更をレビューします。
